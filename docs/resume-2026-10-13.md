### Batch 40a: Super Agents (`ledger-rows/row-852`, `row-770`, the Agents half of `row-745`)

- **The hub.** The AI page has an Ask | Agents switch. The agents hub has All,
  My, Activity and the recently run; the builder and a form; and a profile with
  Message, Run agent, Share, switch off, Clone, Delete, Knowledge and Memory.
- **An agent is its own account** (migration `0189`). It is mentioned, assigned
  and messaged like a person. It is never on the people roster, never notified,
  and never counted in the plan's members or in the credits each member brings.
- **What starts it:** an @mention in a comment or in Chat (answered in that
  thread), a DM, an assignment, its schedule, or an Automation's "Run a Super
  Agent". It acts with the command assistant's tools, under the rights of
  whoever started it.
- **Introduction.** A new agent DMs its maker what it can do.

Tests: `super-agents`, 39 checks, with the model stub and without one; 38
patches and 2 unit ones.

### Batch 40b: the rest of Brain² (`ledger-rows/row-745`, `row-853`)

- **@Brain in a comment.** It is answered by Brain, in that comment's thread.
  Brain reads the task, the thread, and the workspace's public work. It reads
  private work only where it was asked inside it or the comment links it, since
  its answer is read by everybody on the task. The @ picker has frame `04:00`'s
  Brain section, and its Agents section ends in "+ Create Agent".
- **The composer's "+".** It points Brain at a task, a Doc, a list, a folder or
  a space, and gives it files: images, PDFs, sheets, Word documents and text.
- **The decks Brain makes** (migration `0190`). A card shows under the answer.
  The deck is paged as frame `16:55` pages it and is changed by asking again.
  Its versions can be restored, and it can be published to a link anybody may
  open, `/deck/<token>`. The decks are also listed under the AI page's
  Artifacts tab.

Tests: `brain-comments-and-decks`, 29 checks, with the model stub and without
one; 34 patches and 2 unit ones.

## 6. Working rules worth repeating

- **Close each item as ClickUp works it.** In order:
  1. Research ClickUp through web search (the help centre is blocked here).
  2. Build it end to end.
  3. Measure before and after on a lane (the lanes are localhost).
  4. Break-test every check.
  5. Register the suite in `ci.yml`.
  6. Run the preflight and a regression.
  7. Write the ledger, and commit.
- **A suite that needs the model runs both ways.** On a model lane it reads
  the answers. Where no model answers (CI), each check reads the refusal.
- **Name break patches without `.py`,** or use any spelling: the runner now
  reads a set named by file the same as one named by patch.
- **Push only what a rehearsal passed** (`bash scripts/ci-rehearsal/all.sh`).
  `ALLOW_SCHEMA_RESET` stays unset on production deploys.
- **Postgres here allows 100 connections.** Sweep on four lanes at most, and
  stop the APIs of lanes not in use.
- **No subagents or workflows.** The owner asked for the work to be done
  directly, for cost.
- **Commit messages end with the session trailer,** and nothing pushed names a
  model.
