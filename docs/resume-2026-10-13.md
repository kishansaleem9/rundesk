- **The hub.** The AI page has an Ask | Agents switch. The agents hub has All,

  whoever started it.

### Batch 40b: the rest of Brain² (`ledger-rows/row-745`, `row-853`)

- **@Brain in a comment.** It is answered by Brain, in that comment's thread.
  Brain reads the task, the thread, and the workspace's public work. It reads

  The deck is paged as frame `16:55` pages it and is changed by asking again.

  Artifacts tab.

Tests: `brain-comments-and-decks`, 29 checks, with the model stub and without

### Batch 41: a mailbox linked over IMAP (`found-12-oct/task-email-imap-unbuilt`)

- **Sign in with IMAP.** From's "Link an email" and the Email settings offer
  ClickUp's form: the email, the password, the IMAP and SMTP servers and ports,
  and "Requires SSL". The server signs in to both before it keeps the mailbox,
  and says a refusal in the server's words.
- **The password is sealed** (AES-256-GCM under `TOKEN_ENCRYPTION_KEY`, bound to
  its row; migration `0191`). Without the key no mailbox is linked by password.
- **Servers typed by a person are checked:** a private address is refused unless
  the operator names it in `MAILBOX_PRIVATE_SERVERS`; "Requires SSL" is TLS
  (993, 465) or STARTTLS before the password, certificates checked.
- **Sent through its SMTP server** (the Bcc in the envelope only); **its answers
  read from its inbox** in one sign-in a poll, threaded by the first email's
  Message-ID; a refused sign-in marks it to link again; **the AI's drafts** go in
  its Drafts.
- **The lanes' mailbox stub** (`mailbox-stub.mjs`, IMAP and SMTP with STARTTLS)
  starts beside the mail stub; `check-mailbox-stub.mjs --mutate` holds it.

Tests: `task-email-imap`, 14 checks; unit `imap-mail.test.ts`, 9; 28 patches and

## 6. Working rules worth repeating

- **Close each item as ClickUp works it.** In order:
  1. Research ClickUp through web search (the help centre is blocked here).
  2. Build it end to end.
  3. Measure before and after on a lane (the lanes are localhost).
  4. Break-test every check.
  5. Register the suite in `ci.yml`.
  6. Run the preflight and a regression.
  7. Write the ledger, and commit.
- **A suite that needs the model runs both ways.** On a model lane it reads
  the answers. Where no model answers (CI), each check reads the refusal.
- **Name break patches without `.py`,** or use any spelling: the runner now
  reads a set named by file the same as one named by patch.
- **Push only what a rehearsal passed** (`bash scripts/ci-rehearsal/all.sh`).
  `ALLOW_SCHEMA_RESET` stays unset on production deploys.
- **Postgres here allows 100 connections.** Sweep on four lanes at most, and
  stop the APIs of lanes not in use.
- **No subagents or workflows.** The owner asked for the work to be done
  directly, for cost.
- **Commit messages end with the session trailer,** and nothing pushed names a
  model.
