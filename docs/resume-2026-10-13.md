## 6. Working rules worth repeating

- **Close each item as ClickUp works it.** In order:
  1. Research ClickUp through web search (the help centre is blocked here).
  2. Build it end to end.
  3. Measure before and after on a lane (the lanes are localhost).
  4. Break-test every check.
  5. Register the suite in `ci.yml`.
  6. Run the preflight and a regression.
  7. Write the ledger, and commit.
- **A suite that needs the model runs both ways.** On a model lane it reads
  the answers. Where no model answers (CI), each check reads the refusal.
- **Name break patches without `.py`,** or use any spelling: the runner now
  reads a set named by file the same as one named by patch.
- **Push only what a rehearsal passed** (`bash scripts/ci-rehearsal/all.sh`).
  `ALLOW_SCHEMA_RESET` stays unset on production deploys.
- **Deploys are the owner's, by hand** (14 October): on the VPS, this branch
  checked out in `/opt/rundesk`, then `./deploy/deploy.sh rebuild` (it pulls
  the branch, builds, and applies new migrations). PR #1 is not merged into
  `main`; merging it would start `deploy.yml`. Tell the owner the commit a
  rehearsal and CI passed, and set `TOKEN_ENCRYPTION_KEY` in the VPS `.env`
  before the first deploy that holds batch 42.
- **Postgres here allows 100 connections.** Sweep on four lanes at most, and
  stop the APIs of lanes not in use.
- **No subagents or workflows.** The owner asked for the work to be done
  directly, for cost.
- **Commit messages end with the session trailer,** and nothing pushed names a
  model.
