  full run: the one that passed on 1 October (36906129570) took 141
  minutes, one job after another: Verify 25.5, Browser suites 7, the

## 5. Things learned today worth keeping

- (6 October) A container restart does not always end every process. The
  first preflight's unit-claims step outlived one, and went on applying and
  restoring patches for five minutes, under the first steps of the preflight
  run again after it: that run's API unit tests failed on a patch they did not
  cause (`tvs-4` held the next occurrence's start at its due date), and one
  claim (`sip-68`) went falsely green because the file it was patching had
  been restored from the index under it. After a restart, look for
  `check-unit-claims`, `wt-break.sh` and `run-plan.sh` with `ps` and stop
  any survivor by its PID before running anything that reads the tree; then
  `git status` for a patch left applied.
- (5 October) `build-api.sh`, `verify.sh` and `refresh-dists.sh` run from a
  worktree build and test the MAIN checkout (`found-5-oct/lane-scripts-build-the-main-checkout`);
  only `fleet-restart.sh` follows its own tree. Until that item is closed, an
  agent in a worktree uses copies with the path rewritten to its worktree, as
  both revert builders did on 5 October.
- (5 October) A triage agent told not to restart lanes, finding them dead
  after a container restart, brought back only its own lane on the existing
  build, or ran the build privately on a scratch port. Both are safe; name the
  allowance in the brief next time.

- The container can restart mid-run: every lane, runner and Postgres dies.
  `fleet-restart.sh "1 2 3 4 5 6 7"` (with `RUNDESK_LANE_MODEL=2`) brings them
  back; re-queue break sets from their report files (a finished set ends in
  `DONE <suite>`).
- Run the FULL preflight before a commit, not single gates: 8e398c1 broke
  `check-model-lanes.sh`'s mutation 5, which only the full preflight showed.
- Check a staged commit on its own (`git checkout-index -a --prefix=…`) —
  it found the ledger-id gate's own header failing its rule.
- Never `pkill -f` a pattern that appears in your own command line.
- Never edit `apps/` while a sweep runs on a lane, and never let another session run `build-api.sh` then: either one makes the lane's build stale mid-sweep and every later suite is refused (exit 7) — it cost two sweeps today.
- A Radix menu marks the rest of the page `aria-hidden` while it is open or closing: a suite that looks for a button by role right after pressing Escape finds nothing and reads "not offered". Wait for `getByRole('menu')` to be gone first.
- Park a next item's suites and patches outside the tree (a scratch folder) while a preflight runs for the commit before it: `check-suites-registered` and `check-break-patches` read every file in `test/e2e`. Build the next change in a spare worktree meanwhile; bring it in with `git diff | git apply` once the sweep ends.
- drizzle-kit 0.31 does not read `NULLS NOT DISTINCT` back from a database: a schema that says `.nullsNotDistinct()` makes every push want to rebuild the key, and on a table with rows it asks a question no pipe answers — the push stops there, prints the error and exits 0. `fleet-sync.sh` then reports "synced" with nothing pushed, and the schema reference (built from `/tmp/claude-0/pristine.dump` and a push) silently lacks every change after it. Migration 0166 keeps that key in the migration alone. After a migration changes a constraint by SQL, apply it to every lane database and pristine, then re-dump `pristine.dump` and drop `schema-ref.key`.
